# 苹果日程与提醒

本技能读取当前 Mac 系统账户已经同步到本机的 Apple 日历和提醒事项。它不是 iPhone 文件系统访问，也不会读取 Apple ID 密码；是否同步到 iPhone 由用户在同一 Apple 账户的 iCloud 设置决定。

## 使用边界

- 先调用 `get_apple_schedule_status`，确认 macOS 是否已授予完整读取权限。
- 未授权时，明确提示用户前往网页「更多工具 → 日程与提醒」点击授权，并在 macOS 弹窗或「系统设置 → 隐私与安全性」中完成授权；不要声称已经读到日程。
- 当用户问“待办”“待办事项”“我有什么待办”时，**待办事项只指 Apple「提醒事项」**：调用 `list_apple_schedule` 时传 `include_events=false`、`include_reminders=true`。绝不能把项目、日报、会议、聊天上下文中推断出的工作任务混入结果。只有用户明确说“工作任务”或“项目待办”时，才按工作上下文回答。
- 查询日历安排时，调用 `list_apple_schedule` 并传有界 ISO 8601 时间范围；该范围限制日历安排，提醒事项返回全部未完成项（包括无截止日期和逾期项）。默认只说明结果所属的本机 Apple 账户同步数据。
- 输出应区分日历安排与未完成提醒事项，保留时间、目标日历/列表和不确定性。不要把无截止日期的提醒伪装成某个确定时间。

## 写入规则

网页「日程与提醒」只做可视化，用户自己管理日历和提醒事项请使用 iPhone。模型**只能**新增 Apple「提醒事项」，不能新增日历事件。

- 用户在当前对话中明确说“新增/添加/创建待办”或“提醒我……”时，先打开本技能并调用 `create_apple_reminder`。必须把 `user_confirmed=true`；标题、时间、备注只能使用用户明确给出的内容，不能从会议、项目、聊天上下文推断。
- 用户只是在讨论、列计划、说“以后提醒我”但没有要求创建时，不得调用写入工具；先追问或给出草稿。
- 用户没有指定列表时，省略 `list_name`，写入 Apple 系统默认提醒事项列表；指定列表时只能传精确列表名称。用户没有给时间时，省略 `due_at`，不要擅自设定截止时间。
- 成功后明确说明“已新增到当前 Mac 同步的 Apple 提醒事项”；不要说“直接写入 iPhone”。

## 结果表达

- 明确说“从当前 Mac 已同步的 Apple 数据读取到”，不要说“直接读取了 iPhone”。
- 若没有结果，说明是“所查时间范围内未发现”，而不是“没有任何日程”。
- 读取最多返回每类 200 条，超出时必须说明列表已截断，建议缩小时间范围。
