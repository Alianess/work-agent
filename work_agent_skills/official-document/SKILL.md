# 公文

把本技能作为“文种判断、内容结构、正式要素和格式规格”层。不要在这里直接生成 DOCX；最终文件统一交给 `docx` 技能。

## 执行顺序

1. 读取系统上下文中的“公司标准文件格式”。它是公司级纯文字格式覆盖，不是会议事实或公文内容。
2. 判断材料类别：
   - **正式党政机关公文**：用户明确要求正式发文、红头、公文版记、发文字号，或内容明显属于法定文种和机关行文。
   - **公司公文式文字材料**：汇报稿、工作方案、内部会议纪要、调研材料等不要求完整法定公文要素，但采用正式中文排版。
   - **普通 Word 文档**：合同、手册、宣传册、带复杂图表的报告等；退出本技能，直接使用 `docx`。
3. 正式公文先确定行文目的、发文机关与受文机关关系，再选择文种。读取 [文种与结构](references/document-types.md)。
4. 需要确定版面、字体、版记、页码或特殊版式时，读取 [格式规范](references/format-standard.md)。
5. 输出“定稿内容 + 文档规格”，然后打开 `docx` 技能：
   - 调用 `sys_skill(op='open', skill_id='docx')`。
   - 创建、编辑、批注、修订、模板套用、校验和渲染均遵循完整 `docx` 技能；不得改用本技能的简化生成器。
6. 生成后做内容校核、OOXML 校验和页面渲染检查。格式不清楚时不得擅造红头、发文字号、签发人、印章或密级。

## 格式优先级

按以下顺序处理冲突：

1. 用户本轮明确要求或提供的 Word 模板。
2. 系统上下文中的公司标准文件格式。
3. 正式公文适用的 GB/T 9704—2012 和机关专项规定。
4. `docx` 技能的通用设计默认值。

正式党政机关公文不能因为公司格式较简略而漏掉法定要素；公司内部材料也不要机械添加红头、发文字号、签发人、版记和印章。公司格式没有说明的项目，正式公文按国家标准补齐；普通公司材料由 `docx` 技能采用克制、稳定的中文正式文档默认值。

## 文种与内容约束

- 只在确有对应行文关系时使用法定文种，不把“汇报材料”“工作方案”“领导讲话”“简报”冒充法定文种。
- 请示应当一文一事，不得在报告中夹带请示事项。
- 批复必须针对具体请示答复；函主要用于不相隶属机关之间商洽、询问、答复或请求批准。
- 通知强调执行或周知，通报强调典型、情况或精神，报告强调汇报和反映情况。
- 纪要用于记载会议主要情况和议定事项；普通内部会议记录可采用公司公文式排版，但不自动补造正式发文要素。
- 正式文稿不得虚构单位、文号、签发人、日期、密级、紧急程度、主送机关、印章和附件。

## 交给 Word 技能的规格

交接时明确提供：

- 材料类别：正式公文 / 公司公文式文字材料 / 普通 Word。
- 文种及判断依据。
- 完整定稿内容，包括标题、主送机关、正文、附件说明、署名和日期中已确认的部分。
- 应用的公司格式原文；不要自行改写用户设置。
- 正式公文需补充的国家标准要素和特殊版式。
- 未确认而必须留空的字段，以及不得虚构的字段。
- 是否有参考模板、是否需要批注/修订、最终输出路径和验收要求。

## 官方依据

依据状态与来源见 [官方来源](references/sources.md)。GB/T 9704—2012 当前状态为现行，2025年复审结论为继续有效。若用户要求某机关、地方或行业的最新专项格式，先检索该机关现行官方规定；专项规定只覆盖其明确调整的部分。
