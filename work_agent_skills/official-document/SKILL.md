# 公文

本技能负责文种判断、内容结构、正式要素和 GB/T 9704—2012 格式规格。不要在这里直接生成 DOCX；最终文件统一交给完整 `docx` 技能。

## 执行顺序

1. 判断材料类别：
   - **正式党政机关公文**：用户明确要求正式发文、红头、发文字号、签发人、版记，或内容确属法定文种和机关行文。
   - **参照公文格式的正式文字材料**：公司、事业单位或其他组织的汇报稿、工作方案、内部会议纪要、调研材料等。按 GB/T 9704—2012 的通用纸张、版心、字体层级、行数字数和页码规范编排，但只放置真实适用的要素。
   - **普通 Word 文档**：合同、手册、宣传册、带复杂图表的报告等；退出本技能，直接使用 `docx`。
2. 正式公文先确定行文目的、发文机关与受文机关关系，再选择文种。读取 [文种与结构](references/document-types.md)。
3. 只要需要正式中文排版，就读取 [格式规范](references/format-standard.md)。不得再读取、沿用或注入旧的“公司标准文件格式”。
4. 输出“定稿内容 + 文档规格”，然后打开 `docx` 技能：
   - 调用 `sys_skill(op='open', skill_id='docx')`。
   - 创建、编辑、批注、修订、模板套用、校验和渲染均遵循完整 `docx` 技能；不得改用本技能的简化生成器。
5. 生成后做内容校核、OOXML 校验和页面渲染检查。格式不清楚时不得擅造红头、发文字号、签发人、印章、密级、紧急程度、主送机关或日期。

## 格式基线与冲突处理

- 固定基线为 GB/T 9704—2012。原“公司标准文件格式”和账户级自由文本排版覆盖已经废弃，不再参与任何优先级判断。
- 用户本轮明确指定的机关模板或专项规则可以补充基线；若其与国标冲突，先确认适用范围和用户是否明确要求替代，不能把历史公司偏好当作替代理由。
- 具体机关、地方或行业的现行专项规定只覆盖其明确调整且确实适用于本材料的部分。
- `docx` 技能的通用默认值只能处理国标未规定的实现细节，不能改变 A4、版心、字体字号、行数字数、层级和页码等国标要求。

正式党政机关公文应包含业务上真实存在且适用的法定要素；参照公文格式的内部材料不机械添加红头、发文字号、签发人、版记、印章、密级或紧急程度。是否具备公文效力由发文主体、权限、程序和真实要素决定，不由外观决定。

## 文种与内容约束

- 只在确有对应行文关系时使用法定文种，不把“汇报材料”“工作方案”“领导讲话”“简报”冒充法定文种。
- 请示应当一文一事，不得在报告中夹带请示事项。
- 批复必须针对具体请示答复；函主要用于不相隶属机关之间商洽、询问、答复或请求批准。
- 通知强调执行或周知，通报强调典型、情况或精神，报告强调汇报和反映情况。
- 纪要用于记载会议主要情况和议定事项；普通内部会议记录可以参照国标排版，但不自动补造正式发文要素。
- 正式文稿不得虚构单位、文号、签发人、日期、密级、紧急程度、主送机关、印章和附件。

## 交给 Word 技能的规格

交接时明确提供：

- 材料类别：正式党政机关公文 / 参照公文格式的正式文字材料 / 普通 Word。
- 文种及判断依据。
- 完整定稿内容，包括标题、主送机关、正文、附件说明、署名和日期中已确认的部分。
- GB/T 9704—2012 的通用版面规格、实际需要的格式要素和适用的特殊版式。
- 不适用、未确认而必须留空、不得虚构的字段。
- 是否有本轮参考模板、是否需要批注/修订、最终输出路径和验收要求。

## 官方依据

附件全文核对记录、标准状态和官方来源见 [官方来源](references/sources.md)。GB/T 9704—2012 当前状态为现行，2025 年复审结论为继续有效。若用户要求某机关、地方或行业的最新专项格式，先检索该机关现行官方规定。
