# Meeting transcription and minutes specification

## Purpose

Turn a recording or transcript plus user-confirmed facts into two separate outputs:

1. an internal archive that preserves uncertainty and source differences for later review;
2. a concise work-submission document that contains only confirmed, supportable statements.

## Source priority

Use this order when sources disagree:

1. explicit user confirmation;
2. reliable attached material and approved reference documents;
3. the meeting transcript;
4. public research, only as separately-labelled background context.

Do not infer names, organisations, figures, locations, commitments, ownership, technical parameters, or commercial terms from noisy ASR.

## Internal archive

- Preserve the recording and transcript provenance.
- Mark uncertain wording clearly and keep alternatives or source conflicts visible.
- Separate public background research from statements made in the meeting.
- Retain a concise list of items that need confirmation.

## Work-submission document

- Do not mention ASR, uncertainty markers, candidate names, or verification tasks.
- Omit unsupported details instead of making them sound certain.
- Prefer neutral, listener-safe wording such as `会议中提到` or `与会人员围绕…进行了交流` when action ownership is unclear.
- Preserve exact confirmed actions, owners, deadlines, quantities, and resources.
- Use the organisation names and perspective supplied in `work_background` or `confirmed_info`; if absent, write generically.
- Keep the document concise, formal, and appropriate for ordinary workplace circulation.

## Document handoff

When a Word file is requested, send the final Markdown plus semantic roles to the document workflow. Use a user-provided template only when it is authorised for that output. Validate the generated file and visually inspect rendered pages before delivery.
