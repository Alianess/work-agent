## 一、记（write path）

### 0. 三个来源

事实不只来自用户打的字。绝大多数专名是智能体**读**出来的，不是用户**说**出来的。

| 来源 | 从哪来 | 例子 | 怎么处理 |
|---|---|---|---|
| `user` 用户说的 | user / assistant 消息 | "是零次方不是燃气方" | 逐轮闸门 → 抽取 |
| `observed` 智能体读到的 | 工具结果：ASR 转录、docx 正文、网页、搜索结果 | 转录里出现"工信张传涛局长" | **入档时抽一次**，不逐轮 |
| `derived` 智能体做过的 | 工具调用本身 | 写了 `xxx_报市稿.docx` 第 6 版 | 纯规则投影，不调模型 |

**为什么分开：三者经济性完全不同。**

- `user` 内容短、频次高 → 逐轮跑，靠闸门筛
- `observed` 内容长（一份转录几万字）、频次低 → **按文档抽一次**，不能跟着每轮重抽
- `derived` 完全确定 → 一行模型调用都不用，`build_work_ledger` 已经在干这事

**置信度与优先级**：`user` 说的压过 `observed` 读到的。
转录里 ASR 把名字听成"燃气方"，你后来纠正成"零次方"——冲突时永远听你的。
`observed` 出来的事实默认 confidence ≤ 0.7，且承诺类（"工信请我们牵头写材料"）标记为**待确认**，
主动问你一句再入库，不擅自当成你的待办。

### 1–3. 用户轮次的三级漏斗

越靠前越便宜，把绝大多数轮次挡在模型调用之前。

```
每轮对话结束
   │
   ├─[1] 闸门（纯规则，零成本）───────► 大多数轮次在这里被丢掉
   │        这轮有值得记的东西吗？
   │        没有 → 结束
   │
   ├─[2] 抽取（一次小模型调用）
   │        结构化输出：一次返回本轮所有槽位的候选事实
   │
   └─[3] 调和（纯规则，零成本）
            与库里同 (kind, subject) 的旧事实比对
            → ADD / UPDATE / NOOP
            → 落成 memory/fact 事件，追加进会话日志
```

#### 闸门：什么轮次直接跳过

已实现（`gate_turn`）。实测 9 轮真实对话只有 3 轮过闸。

明确跳过的形态：
- 纯查询（"这个文件在哪"、"帮我看下这段代码"）
- 纯 ASR 转录任务（跑个转录，没有对话内容）
- 纯执行（改个文件、跑个测试，没有新约定产生）

放行的信号（宁可多放，假阳性只花一次小模型调用，假阴性丢一条事实）：
- 时间词（明天 / 周三前 / 8月20日 / 截止）
- 承诺动词（交、提交、出、写、报、安排、负责、跟进、提醒我）
- 纠正词（不是、应该是、其实是、改成、就是）
- 周期性（定期、每周、双周、常态化）——**没有日期但会悄悄失效的义务**

#### 抽取：一次调用，多个槽位

一次模型调用读完本轮，结构化输出一个候选列表。不是每个类别调一次。

| kind | 记什么 | 例子 | 谁消费 |
|---|---|---|---|
| `commitment` | 承诺、待办、提醒事项 | "报市材料周三前提交" | 到期提醒（注意力层） |
| `entity` | 人物/机构/项目的正名与别名 | "是零次方，不是燃气方" | 别名归并 + **ASR 热词** |
| `preference` | 口吻、格式、工作习惯 | "报告用业务员口吻，别写成咨询稿" | 写材料时注入 |
| `decision` | 定下来的事 | "牵头单位定为工信局" | 回忆检索 |
| `setting` | 用户要求的长期默认值 | "以后双周报默认发给孔总" | 配置项 |

输出 schema（每条）：

```json
{
  "kind": "entity",
  "subject": "零次方",
  "statement": "公司正名为零次方，曾被误写为燃气方、云智方",
  "aliases": ["燃气方", "云智方"],
  "due_at": "",
  "confidence": 0.9,
  "source": "user"
}
```

**硬约束：每轮最多 5 条候选，confidence < 0.5 丢弃。**
一轮对话真正值得记的东西不会超过 5 条；超了说明模型在凑数。

#### 调和：不让库越长越肥

已实现（`reconcile`）。按 (kind, subject) 找旧事实：

- 说的是新东西 → **ADD**
- 同一件事有了新说法（改期、改名、改口径）→ **UPDATE**，旧的被覆盖不是新增一条
- 只是重复 → **NOOP**，什么都不写

**这是记忆量控制的主力。** 同一件事你说十遍，库里还是一条。

### 4. observed 通道：入档时抽一次

触发点是**新外部内容第一次进入系统**，不是每轮：

- ASR 转录跑完 → 抽一次
- 读入一份 docx / pdf → 抽一次
- 抓了个网页 → 抽一次

同一份文档不重抽（按内容哈希去重）。抽取范围比 user 通道**窄**：
只要 `entity`（人名、机构、项目名）和 `decision`，不要 `preference` / `setting`——
那些只能由你本人定，文档里读到的不算。

长文档分段抽，但**只保留跨段去重后的结果**，单份文档上限 30 条实体。

### 5. 生命周期

| kind | 何时失效 |
|---|---|
| `commitment` | 到期或标记完成后归档，不再进上下文 |
| `entity` | 长期有效（名字不会过期） |
| `preference` / `setting` | 被新的同 subject 事实覆盖 |
| `decision` | 长期保留，但只在检索时出现，不常驻 |

## 二、回忆（read path）

**核心原则：不是每轮把记忆一股脑倒进上下文。** 分两层，预算分开。

### A 层：常驻（每轮都在，极小）

不检索，直接注入系统提示。只放数量天然就少的东西：

- 未到期的 `commitment`（上限 10 条）
- 全部 `preference` + `setting`（本来就没几条）

**预算上限 800 token。** 超了按 due_at 就近截断。

### B 层：按需检索（V5_dev 那套）

不是每轮跑。**做成一个 `recall` 工具，模型觉得需要才调**——就像人想不起来才去翻笔记，而不是说话前先把笔记全背一遍。

触发：
- 用户问句指向过去（"上次我们怎么定的"、"那个材料改到第几版了"）
- 模型自己判断需要背景

管线（照搬 `retrieval_engine.py`，语料换成会话日志 + 文件库）：

```
query
  ├─ BM25（jieba 分词）      top 20 ┐
  └─ dense（FAISS 向量）     top 20 ┘
                    ↓ RRF 融合（k=60，不依赖分数同尺度）
                    ↓ cross-encoder 精排
                    ↓ top_k = 6
```

**预算上限 3000 token**：top_k ≤ 6，单条正文截断 500 字，超出只给标题 + 定位（让模型想看再去读原文）。

### C 层：不进上下文的消费者

`entity` 事实还有一个用法**完全不经过上下文**——直接投影成 ASR 热词表喂给转录引擎。
这条链路不占 token，所以不受上面两个预算约束。

## 三、量控总表

| 环节 | 手段 | 上限 |
|---|---|---|
| 记 · 筛轮次（user） | 规则闸门 | 实测约 1/3 轮次过闸 |
| 记 · 外部内容（observed） | 按文档抽一次，内容哈希去重 | ≤ 30 条实体 / 文档 |
| 记 · 智能体产出（derived） | 纯规则投影，不调模型 | 无成本 |
| 记 · 单轮产出 | 抽取硬上限 | ≤ 5 条 / 轮 |
| 记 · 质量 | confidence 阈值 | ≥ 0.5 |
| 记 · 去重 | 调和 ADD/UPDATE/NOOP | 同 (kind, subject) 恒为 1 条 |
| 记 · 老化 | 到期归档 | commitment 完成即出库 |
| 回忆 · 常驻 | 只放承诺 + 偏好 | ≤ 800 token |
| 回忆 · 检索 | 工具式触发 + top_k 截断 | ≤ 3000 token，≤ 6 条 |

## 四、为什么事实落在会话日志里，而不是单独一张表

事实是 `memory/fact` 事件，追加进同一条会话日志，和"用户发了条消息""助手调了个工具"同一个流。

- 每条事实都能追溯到产生它的那一轮
- 重放日志能复现整个记忆库
- 没有第二个数据源要维护、要同步、要担心不一致

"实体表""热词表""记忆库"都不是独立存储，是这条日志的**投影**——和 `build_work_ledger` 从日志投出 49 个产物是同一个机制。

**自检判据**：把 `web_server.py` 里手写的 `ATTENTION_ALIAS_GROUPS` 整段删掉，别名归并仍然工作。
那 5 组本来就在历史对话里说过，真从日志读就一定读得到。删了就不工作，说明还在吃硬编码。
